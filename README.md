# Электронная очередь в прачечную

Общежитие №8 ИрГУПС. Рабочее место оператора для записи студентов на стирку на PHP и MySQL.

[![Проверка бронирования](https://github.com/SoftyMaNA/dorm8-laundry-queue/actions/workflows/php-tests.yml/badge.svg)](https://github.com/SoftyMaNA/dorm8-laundry-queue/actions/workflows/php-tests.yml)

## Возможности

- Создание бронирования и запрет пересечений на одной машине.
- Учёт машин, находящихся на обслуживании.
- Отмена с сохранением истории и освобождением времени.
- Уведомления о создании и отмене записей.
- Четыре автоматических теста с настоящей базой MySQL.

Прачечная работает с 08:00 до 22:00. Соседние интервалы разрешены: запись 10:00-11:00 не мешает записи 11:00-12:00.

## Запуск

Нужны PHP 8.3+ с расширением `pdo_mysql`, MySQL 8.0+ и Git.

1. Клонировать репозиторий:

   ```sh
   git clone https://github.com/SoftyMaNA/dorm8-laundry-queue.git
   cd dorm8-laundry-queue
   ```

2. В MySQL создать пустую базу `laundry_queue` с кодировкой `utf8mb4` и пользователя с правами на эту базу.
3. Создать файл `.env` по образцу `.env.example`, указать свои параметры подключения.
4. Подготовить таблицы и начальные данные:

   ```sh
   php bin/init-db.php --seed
   php -S 127.0.0.1:8080 -t public
   ```

5. Открыть `http://127.0.0.1:8080`.

Начальные данные: три условных студента, один сотрудник и пять машин. M05 находится на обслуживании. Повторно запускать `--seed` для заполненных справочников нельзя; для обновления структуры используйте `php bin/init-db.php`.

Интерфейс предназначен для локального рабочего места оператора. Самостоятельный вход студентов, проверка прав, почтовая рассылка и интеграция с пропускной системой в эту версию не входят. Не публикуйте интерфейс в открытом доступе без аутентификации и разграничения прав. Уведомления хранятся в базе и отображаются на странице.

## Тесты

Создать отдельную базу с именем `laundry_queue_test`, настроить подключение к ней в переменных окружения или отдельной копии `.env` и выполнить:

```sh
php tests/run.php
```

Тесты откажутся работать с именем базы без суффикса `_test`. Они создают собственные записи и удаляют их после проверки. Таблицы остаются в тестовой базе. Для запуска одного сценария: `php tests/run.php 2`.

| № | Проверка | Ожидаемый результат |
|---|---|---|
| 1 | Свободное время | Активная бронь и уведомление сохранены |
| 2 | Пересечение интервалов | Конфликт отклонён; соседнее время и другая машина разрешены |
| 3 | Обслуживание машины | Бронь и уведомление не создаются |
| 4 | Отмена записи | Время освобождено, история отмены сохранена |

В Actions эти сценарии видны как четыре отдельных шага. Отчёты JUnit сохраняются в артефакте `booking-test-results`.

## GitFlow

`main` содержит выпуски, `develop` используется для разработки. Новые функции создаются в `feature/*`, подготовка версии выполняется в `release/*`, исправления выпущенной версии - в `hotfix/*`. Слияния сохраняются в истории Pull Request. Время коммитов соответствует времени выполнения операций.
