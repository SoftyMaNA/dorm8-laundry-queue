# Структура данных

Файл `database/schema.sql` создаёт пять таблиц InnoDB с кодировкой utf8mb4.

| Таблица | Первичный ключ | Назначение | Внешние ключи |
|---|---|---|---|
| students | id_student | ФИО, комната, активность студента | Нет |
| staff | id_staff | Сотрудник, должность и организационная роль | Нет |
| washing_machines | id_machine | Уникальный код, модель и доступность машины | Нет |
| bookings | id_booking | Машина, студент, интервал и статус записи | id_student, id_machine |
| notifications | id_notification | Текст уведомления и время создания | id_student |

Один студент имеет много бронирований и уведомлений. Одна машина имеет много бронирований. Таблица сотрудников пока самостоятельная: действия выполняются через локальное рабочее место без учётной записи.

Для поиска пересечений служит индекс `idx_machine_interval (id_machine, status, start_time, end_time)`. Ограничение `CHECK` требует окончания позже начала. Внешние ключи препятствуют удалению связанных справочников. При отмене бронирование не удаляется.

Перед проверкой конфликта сервис блокирует строку выбранной машины с `SELECT ... FOR UPDATE`. Два одновременных запроса на одну машину выполняются последовательно в транзакциях. Проверка пересечений также использует блокирующее чтение, которое видит актуальные записи. Четыре теста проверяют бизнес-сценарии последовательно; нагрузочное испытание параллельных запросов в их состав не входит.

Начальные записи из `database/seed.sql` не содержат реальных персональных данных. M05 недоступна. Тестовые записи изолированы в отдельной базе и очищаются после каждого сценария.
