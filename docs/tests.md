# Четыре автоматических теста

Проверки обращаются к `BookingService`, используемому веб-страницей, и к настоящей MySQL. Подмена сервиса или заранее записанный результат не применяются. Проверяется состояние таблиц после операций.

| № | Входные условия и действие | Что проверяется |
|---|---|---|
| 1 | Активный студент, доступная машина, 10:00-11:00 | Получен номер; в bookings статус active; в notifications одно сообщение |
| 2 | Уже занято 10:00-11:00 | Отклонены частичное пересечение, совпадение и охватывающий интервал; лишние записи отсутствуют; соседний интервал и другая машина разрешены |
| 3 | Машина имеет is_available = 0 | Операция отклонена; бронь и уведомление отсутствуют |
| 4 | Создать, отменить и снова занять тот же интервал | Старая запись cancelled; новая имеет другой номер; активна одна запись; сохранены три уведомления |

Файл `tests/run.php` содержит ровно четыре тестовых сценария. Отдельные утверждения внутри сценария уточняют его ожидаемый результат. Номер теста можно передать аргументом от 1 до 4. Неверный номер или имя рабочей базы завершают запуск с ненулевым кодом.

## Автоматизация

Workflow `.github/workflows/php-tests.yml` запускается при push, Pull Request и вручную. Он поднимает MySQL 8.0, подготавливает PHP 8.3, проверяет синтаксис и выполняет четыре отдельных шага. Следующие тесты выполняются и после ошибки предыдущего, если запуск не отменён. Файлы JUnit сохраняются в артефакте `booking-test-results`.

Первый проверенный Pull Request: [№3](https://github.com/SoftyMaNA/dorm8-laundry-queue/pull/3). [Успешный запуск Actions №2](https://github.com/SoftyMaNA/dorm8-laundry-queue/actions/runs/42213522498) подтвердил прохождение всех четырёх шагов.

Это интеграционные проверки модуля бронирования. Проверка внешнего вида, нагрузка, аутентификация и доставка электронной почты ими не подтверждаются.
